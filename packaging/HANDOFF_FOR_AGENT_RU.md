## С чего начать другому агенту

1. Проверь `PACKAGE_MANIFEST_SHA256.tsv` командой `python VERIFY_PACKAGE.py`.
2. Прочитай этот файл, `CHECK_BEFORE_DEMO_RU.md` и
   `algorithm/NEW_DATA_RUNBOOK.md`.
3. Если нужен запуск сайта и новые расчёты на Windows x64, запусти
   `powershell -ExecutionPolicy Bypass -File .\START_BEEGO.ps1` из корня.
4. Не меняй `data/dataset` при проверке воспроизводимости. Новые загрузки
   создают отдельный датасет; их нельзя подменять опубликованным 17 августа.

## Запуск

Нужны Windows x64, PowerShell, Python **3.13 x64** и Docker Desktop. Node.js
включён. Скрипт `START_BEEGO.ps1` устанавливает Python-зависимости из
локального wheelhouse в `.venv`, загружает Docker-образ при необходимости,
поднимает Valhalla на `127.0.0.1:8002`, API на `127.0.0.1:8787`, сайт на
`127.0.0.1:5173`. При уже запущенном совместимом Valhalla повторно его не
запускает. Если Docker Desktop или Python отсутствуют, сайт с готовыми
результатами можно запустить отдельно, но новый точный расчёт будет недоступен.

Ключи `GEOAPIFY_API_KEY`, `YANDEX_RASP_API_KEY` и `DGIS_ROUTING_API_KEY`
сохранены в `site/.dev.vars` и `.env.routing.local`; резервная копия Geoapify
лежит в `credentials/site.dev.vars.backup`. Архив содержит секреты: его нельзя
публиковать в GitHub или передавать третьим лицам. Если ключи будут переданы
посторонним, их нужно перевыпустить. 2GIS не используется для текущего
Valhalla-плана, но конфигурация сохранена по просьбе владельца.

## Как считается новый день

Импорт проверяет формат, адреса, координаты, окна, навыки, транспорт и
оборудование. Если координат нет, Geoapify геокодирует адрес; неясный или
неподтверждённый результат не превращается в выдуманную точку. Для
общественного транспорта индекс строится под дату из GTFS, снимка поездов
и схемы метро. Сначала быстро строятся дорожные матрицы и план; затем
Valhalla и независимый валидатор проверяют все поездки и ограничения.

Если после обычного расчёта остаются аварии, включается ограниченный поиск:
сначала вставка без потерь, затем допустимый обмен с обычными заявками,
потом более широкий поиск. Каждое изменение проходит точную маршрутизацию
и полную валидацию. Если авария остаётся, статус `UNRESOLVED` означает, что
ограниченный поиск её не назначил; это **не доказательство** математической
невозможности. Общий бюджет нового дня по умолчанию 840 секунд.

Текущий опубликованный 17 августа был повторно рассчитан с пустым кэшем
точных маршрутов и готовыми проверочными матрицами: снова 205/205, 0
нарушений. Более ранний полный холодный прогон включал также построение
матриц и занял менее пяти минут. Скорость и покрытие для произвольного
будущего набора не гарантируются заранее.

## Полезные команды

```powershell
python VERIFY_PACKAGE.py
& .\offline-assets\node\node.exe site\scripts\verify-algorithm-integration.mjs
cd site
& ..\offline-assets\node\node.exe --test tests\published-exact-history.test.mjs
```

Также проверены 69 тестов сайта, 41 профильный тест Python, сборка Vite и
установка Python 3.13 x64 целиком из вложенных wheel-файлов. Полный старый
`unittest discover` нельзя использовать как проверку этого комплекта:
несколько исследовательских тестов привязаны к отвергнутому
`algorithm/work/dataset_v21`, старому плану на 28 бригад и `h5py` для
офлайн-подготовки Traffic4cast. Рабочие исходники, выбранный набор и
проверенные результаты находятся в каталогах, указанных выше.

Для точного расчёта другого дня используй
`algorithm/tools/run_new_dataset_pipeline.py` и
`algorithm/NEW_DATA_RUNBOOK.md`; не используй старые файлы из архивов/веток
как вход. Docker-маршрутизатор должен отвечать на `/status`, а итоговый план
должен иметь `EXACT_VALID` и `validation.status=VALID`.
