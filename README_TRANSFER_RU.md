## Перепланирование

Кнопка «Пересчитать план» на карте открывает «Ход смены → Изменить план». Отдельная вкладка «Перепланирование» под «Ходом смены» открывает тот же механизм. Можно выбрать расчёт до начала смены (07:00) либо с заданного времени в течение дня. Сервер сохраняет черновик, показывает разницу по назначениям, времени, очереди и пробегу и публикует новую версию только после независимой точной проверки. Начатые и прошедшие визиты остаются на своих местах.

Новую заявку для такого черновика можно ввести вручную или загрузить из CSV, JSON, XLS, XLSX. Русские названия колонок распознаются автоматически. Адрес можно выбрать из московских подсказок Geoapify; также можно указать точку на карте без адреса. Добавление сначала создаёт черновик, затем точный алгоритм строит изменённый план. Тестовая заявка не публикуется автоматически.

Для исторических дней алгоритм берёт соответствующие датасет, проверенный план и исходные остатки оборудования из `history/ГГГГ-ММ-ДД/` первого архива. Эта папка необходима для пересчёта исторических смен. Она входит в переносимый архив проекта; в Git хранится код и облегчённая основа без 2,24 ГБ исторических артефактов. Если локальный транспортный индекс из истории недоступен, сервис собирает его из исходных транспортных данных при первом расчёте.

## Что означают исторические дни

17 августа 2026 года — основной набор, точный план 205/205. Остальные 181 день, с 17 февраля по 16 августа, в первом архиве имеют отдельные **синтетические входные наборы** и независимо проверенные точные планы. Это проверенные результаты модели, а не записи о фактически исполненных визитах. Отсутствующие факты не заполнены вымышленными отметками. Интерфейс показывает происхождение исторического плана.

## Запуск

На Windows x64 с Python 3.13 и Docker Desktop выполните из этой папки:

```powershell
powershell -ExecutionPolicy Bypass -File .\START_BEEGO.ps1
```

Откройте `http://127.0.0.1:5173/`. Скрипт использует встроенный Node.js, ставит Python-пакеты из локального wheelhouse и запускает API. Точный расчёт новых данных требует доступной Valhalla. Если проверка дорог или ограничений не пройдена, публикация отклоняется; приблизительный маршрут не подставляется.
