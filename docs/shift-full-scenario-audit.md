# Проверка полного хода смены · 19.10.2026

Ветка: `codex/shift-full-scenario-audit`. Проверки выполнялись в отдельных QA-сменах на 8788, в собственном headless Chromium. Данные, решения и расчёты рабочего оператора в испытаниях не изменялись.

## Найдено и исправлено

1. Следующая транспортная волна ожидала применения предыдущего результата. Создание события теперь независимо от решения оператора и занятости планировщика. Все ограничения сохраняются, новый расчёт проверяет их общий актуальный контекст.
2. Чтение состояния сценария блокировалось HTTP 429 во время подготовки геометрии события. Чтение durable-состояния больше не захватывает блокировку изменения.
3. После HTTP 429 от занятого планировщика запуск мог не повториться на остановленных часах. Контроллер повторяет запуск раз в две секунды, показывает ожидание, отменяет только устаревший расчёт этой же смены и не создаёт дубль текущего. Отменённый или действительно неуспешный расчёт сам не перезапускается. Ожидание снимается и при запуске другим оператором.
4. Быстрая отмена воспроизвела `write EPIPE`: Python завершался, пока Node ещё записывал большой пакет в stdin. Необработанная ошибка завершала API-процесс. Каналы ввода расчёта, полного построения смены и проверки сети теперь обрабатывают закрытие; завершение проходит через штатный close/reject, освобождая планировщик. Проверка отмены до/после подготовки не даёт запустить новый решатель после отмены. У расчёта и независимого аудита общий предел 15 минут, при отказе сохраняется опубликованный план.
5. Транспортное предупреждение из-за слова «маршрут» ошибочно получало заголовок «Маршруты построены». События имеют явный тип `TRANSPORT_EVENT` и заголовок о проблеме, независимо от эвристики обычных уведомлений.

## Конкуренция, отмена, восстановление

Транспортная QA-смена `9b518ab2-683c-48c1-b2bb-ca9e3d9c685b` и отдельная аварийная `f079b6c6-ee32-4f48-9c89-d26af9c43d63`:

- Реальный аварийный поиск занимал общий планировщик. Дорожное событие 09:30 появилось на карте, часы остановились на 570-й минуте, интерфейс сообщил об автоматическом ожидании расчёта.
- Первое проверенное аварийное предложение появилось через 4,630 с. Часы аварийной смены продвинули с 11:17 до 11:18; актуальное подтверждение Ионова Геннадия завершилось `ACCEPTED/APPLIED` за 6,941 с, выбранный инженер сохранился.
- После освобождения планировщика дорожный расчёт запустился без нового движения часов и завершился `READY/VALID` за 3,781 с.
- Первый результат оставили неприменённым. Событие 14:25 возникло при открытых общих «Заявках», вернулось на карту «Хода смены» и не опубликовало план самовольно: ревизия осталась 1.
- Реальная быстрая отмена после исправления завершилась `CANCELLED`, API остался доступен; за контрольные три секунды расчёт сам не возобновился.
- Повторный запуск проверил обе сохранённые проблемы, завершился `READY/VALID` за 69,433 с и применился.
- Дополнительная одновременная дорога и метро в QA-смене `b5159e19-5f85-4de9-957e-25a90f9d1da5`: `VALID/APPLIED`, 54,732 с.

Восемь последовательных отмен с задержками от 0 до 1000 мс после запуска завершились за 23–349 мс. После каждой API health отвечал, следующий расчёт занимал освободившийся слот; ревизия и SHA опубликованного плана не изменились.
