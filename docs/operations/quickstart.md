# Полный запуск BeeGo!

Нужны Git, Docker с Compose и Linux-контейнерами, интернет для загрузки образов и около 15 ГБ свободного места. Node.js, Python и зависимости устанавливаются внутри образа. Дорожные и транспортные ресурсы входят в репозиторий; Git LFS не требуется.

## Первый запуск

Получите ветку с этой документацией через Git либо **Code → Download ZIP**. Из корневого каталога:

```bash
docker compose -f compose.complete.yaml up --build -d
docker compose -f compose.complete.yaml ps
```

Откройте **http://127.0.0.1:8787/**. На Windows можно запустить корневой `START_BEEGO.ps1`.

Первый запуск проверяет SHA-256 ресурсов, распаковывает их в Linux volumes и создаёт контрольную базу. Дождитесь завершения `runtime-setup` с кодом 0 и состояния healthy у `valhalla` и `app`:

```bash
docker compose -f compose.complete.yaml logs --tail=40 runtime-setup valhalla app
```

API должен отвечать на `/api/health`, а `/api/runtime/readiness` — возвращать `ready: true`. Сохраняйте имя Compose-проекта при последующих запусках: от него зависят имена volumes. Если порт занят, задайте `BEEGO_HTTP_PORT` до запуска.

## Контрольный день

Откройте «Ход смены». Явная перемотка на 06:00 начинает новый прогон. В 09:30 появляется дорожное ограничение, в 11:17 — авария, в 14:25 — закрытие метро. События видны на общей карте; новое событие открывает соответствующий раздел решения. Скорость можно менять всегда.

Для аварии дождитесь проверенного предложения, выберите инженера и подтвердите направление. Для транспортной проблемы сравните фиолетовый исходный путь с зелёным новым и примените проверенный план. Первый расчёт с холодным кэшем может занимать несколько минут; прогресс и фактическое время отображаются в интерфейсе.

## Обновление и остановка

Перед обновлением сохраните согласованную резервную копию:

```bash
docker compose -f compose.complete.yaml exec app node scripts/backup-shifts.mjs
```

Скопируйте полученную копию из контейнера на отдельный носитель. Путь выводится командой. После получения новой версии:

```bash
docker compose -f compose.complete.yaml up --build -d
docker compose -f compose.complete.yaml stop
```

Повторное включение — `docker compose -f compose.complete.yaml up -d`. Не используйте `down -v` для обычного обновления: эта команда удаляет постоянные volumes.

## Состав и конфигурация

Постоянные volumes содержат операционную базу, расчёты и кэши; дорожные и транспортные volumes отделены от них. Собственные ключи внешних сервисов задаются серверными переменными из `.env.docker.example`. Без ключей работает контрольный сценарий и локальная маршрутизация.
