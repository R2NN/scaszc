# Интеграция рейтинга в актуальный BeeGo

Основа: `39ce945` (`codex/fix-dispatch-confirmation-refresh`). Выборочный перенос из `88ea34578ba816787cb14fd93761707cf58d48e4`, ветка `рейтинг`. Интеграционная ветка: `codex/integrate-engineer-ratings`. Main не изменён.

## Что подключено

- Рейтинг: каталог, поиск, сортировка, фильтры, карточки, вся история оценок, исходные звёзды и объяснение формулы.
- Состав и план: обе границы рейтинга, предложение конкретных людей, подтверждение, точная проверка маршрутов, независимые сценарии и сохранённые версии; потребность по районам и прогноз доступны отдельно.
- Отзывы и разборы: очередь, просмотр/важность, переписка, фото, решения и повторное открытие. Уточнение звёзд требует подтверждения клиента; старое значение сохраняется.
- Общие имена и уникальные портреты по стабильному ID; 32 основных портрета, три основных инженера с инициалами, отдельный portrait-9 для RATING-0001, резерв с инициалами. Только известный префикс moscow: нормализуется, чужие региональные ID не объединяются. Исходные ФИО, ID, ссылки на факты и координаты расчёта не переименовывались.
- Показать ещё / Скрыть в текущем меню; Перепланирование и остальные дополнительные разделы сохранены. Прокручивается навигация, нижние действия остаются доступны.

API `/api/ratings/*` подключён к существующему `createOperationsApi`, следовательно доступен и через `server/main.mjs`. Сущности качества находятся в таблицах `rating_*`. Новые production-зависимости не добавлены.

## Адаптация к текущей версии

Рабочие `replanning.py`, `validator.py`, `replan_ui_event.py`, `shiftDomain.js`, сервер аварий, очередь подтверждения, часы и домашние старты не заменялись. В App и ShiftWorkspace перенесены только интеграционные точки и отображение людей.

Поиск источника рейтинга поддерживает актуальную базу сложности объектов, сохранённые точные результаты, историю и проверенную базу домашнего старта. Новый `rating_inputs.py` проверяет совпадение исходных координат, смен, навыков, оборудования, окон, приоритетов и длительностей до повторного использования доказанных дорог. Несовпадение требует нового проверенного рабочего плана; подстановка офиса вместо дома запрещена. Предложения состава защищены версией качества, ревизией и отпечатком входных данных.

Фиктивная история качества/резерв перенесены в качестве изолированных учебных записей из исходной поставки; они не создают выполненных визитов рабочей смены. Синхронизация настоящего завершённого визита определяет исполнителя по опубликованной версии на момент факта.

## Ограничения результата

Проверенный исходный рабочий день содержит 203 назначения из 205. Подбор состава сохранил это покрытие, сократил число используемых инженеров с 34 до 33; глобальная минимальность не доказана. Эти два неназначенных заказа не скрываются и не считаются выполненными. Неполный или гипотетический состав нельзя сохранять как готовый полный состав. Прогноз остаётся оценкой потребности без обещания адресных маршрутов и SLA. Новые или неподтверждённые домашние координаты требуют расчёта, а не повторного использования старых дорог.
