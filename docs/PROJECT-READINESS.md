## Итог и границы

Рабочий локальный демонстрационный стенд запускается, алгоритм принимает новые данные поддерживаемого формата и публикует только независимо проверенные результаты. Нельзя обещать назначение всех заявок при любых входах: обязательные ограничения сохраняются, невозможные назначения остаются в очереди. Глобальная оптимальность и качество на произвольных реальных данных этой проверкой не доказываются.

В Git находится полный исходный код интерфейса, API и Python-алгоритма, зависимости с lockfile, контрольные наборы и артефакты, модели/сводки, тесты, документация и Dockerfile. Git-ветка не является автономным архивом всего локального стенда.

## Найденные и исправленные проблемы

1. Чистый pnpm пытался компилировать `better-sqlite3` на Windows без C++ toolchain, хотя пакет 13.0.3 уже содержит готовые платформенные модули и `gypfile: false`. Для него отключён лишний build hook, esbuild остаётся разрешён. Версия pnpm закреплена на 11.25.0 и совпадает в Dockerfile и `packageManager`. Минимальный Node — 22.13. Правило управления сборками описано в [документации pnpm](https://pnpm.io/cli/approve-builds).
2. Два теста рассчитывали на существование локального `runtime/qa/`. В чистом checkout его нет. Тесты используют собственные каталоги в системной временной папке и больше не зависят от подготовленного стенда.
3. Docker не копировал уже сохранённые в Git `data/traffic4cast/moscow-2019.json` и `.bin`. Из-за этого дорожная предварительная проверка блокировала новый автомобильный расчёт. Профиль включён в образ; прочие большие источники в контекст не добавлялись. Алгоритм и ограничения не изменены.

## Что переносится отдельно от Git

- **Рабочая база:** `runtime/qa/tz3/ui.sqlite3`. Она содержит текущие смены, отзывы и решения. Переносить согласованную SQLite-резервную копию, созданную штатным `site/scripts/backup-shifts.mjs`, а не один файл открытой WAL-базы.
- **Исходный архив истории:** `history/`. Сейчас это junction на `A:/BeeGo_MERGED_2026-09-29/history`; при переносе нужны сами файлы, а не ссылка. Сводка аналитики в Git не заменяет этот архив. В пустой базе из Git доступна операционная смена 17 августа; 181 предыдущая смена требует архива или существующей базы для просмотра.
- **Дорожные и транспортные ресурсы:** tiles/сервис Valhalla, GTFS и схема метро из `offline-assets/transit-sources/`, готовые индексы `data/transit/*.sqlite` либо источники для их повторной сборки. Недельный архив железнодорожных снимков есть в Git, но он не заменяет GTFS, метро и Valhalla.
- **Расчётные артефакты опубликованных пользовательских планов:** соответствующие `runtime/ui-runs`, `runtime/exact-replans`, `runtime/rating-runs`. Сохранённые версии могут ссылаться на них; при обновлении стенда их сохраняют вместе с базой и проверяют пути при смене корня установки.
- **Локальная конфигурация:** серверные переменные и ключи внешнего геокодирования/AI/расписаний, только если используются эти функции. Секреты в Git не добавляются.
- **Среда:** Node/pnpm, Python с зависимостями и запущенный маршрутизатор. `START_BEEGO.ps1` относится к полному офлайн-архиву со встроенными средами; один Git-clone не содержит `offline-assets/node`, Python wheelhouse и OSM tiles.

Для реальных клиентских данных прежние требования к домену, HTTPS и контролю доступа остаются в силе: [эксплуатация](operations.md). Подключённой GPS-телеметрии нет, движение демонстрируется по плану.

Визуальная браузерная проверка в этом аудите не выполнена: инструмент по-прежнему отвечает `Local browser use is disabled in Work settings`. Подтверждены установка, сборка, HTTP API, расчёты и автоматические проверки; результат не выдаётся за новый визуальный прогон.
