## Подключение и сохранность

`homeStartScenario.mjs` применяет подготовленный план только к новой сессии совпадающей даты, исходного плана и полного состава исходных заказов/инженеров. Смена с другими снимками длительности, изменёнными ограничениями или пользовательским импортом сохраняет свой план. Уже исполняющиеся и архивные сессии не изменяются. На живом стенде создаётся новый прогон с 06:00; первоначальная смена остаётся 203/205 в истории.

Сжатые полные вход и точный план, нормализованный dataset и manifest находятся в `algorithm/artifacts/tz3/home-starts/`. SHA проверяются при загрузке; точный исходный артефакт регистрируется с метаданными для следующих аварийных расчётов. Адреса старта отмечены в «Бригадах», в настройке старта и в карточке домашнего выезда.

Воспроизведение локального поиска:

```powershell
$env:PYTHONPATH='algorithm/src'
python algorithm/tools/repair_home_start_plan.py --source-dataset data/object-complexity/dataset --source-plan algorithm/artifacts/complexity/initial-exact.json --dataset algorithm/artifacts/tz3/home-starts/dataset --engineer SOUTHEAST-ENG-04 --job SOUTHEAST-40698 --cache runtime/ui-shared-cache/routing-cache.sqlite3 --transit-index data/transit/moscow_2026-08-17.sqlite --output runtime/home-starts-reproduced.json
```

Для воспроизведения нужны Python-зависимости, локальная Valhalla и транспортный индекс. Входы и сжатый план проверяются манифестом; повторный расчёт не меняет исполняющуюся сессию. Общие проверки и настольные экраны — в [приёмке](../development/validation.md) и [главном README](../../README.md#emergency).
