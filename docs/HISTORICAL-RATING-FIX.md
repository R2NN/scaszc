# Подбор рейтингового состава на прошлые даты

## Причины

После подключения полного архива рейтинг продолжал сопоставлять текущий постоянный состав с профилем другой смены. Дата первого автоматического заполнения реестра (17 августа) ошибочно применялась как дата найма для прошлых дней. Дополнительно старый импорт терял код территории и подставлял оснащение из базового файла вместо оснащения выбранного дня.

## Исправление

- Каталог рейтинга использует график, навыки, транспорт и стартовые координаты выбранной смены по стабильному ID инженера.
- Членство в независимо проверенной исторической смене подтверждает присутствие в её составе. Оно не отменяет явную недоступность, не делает будущий найм доступным и не меняет периоды реестра текущей смены.
- Адаптер чтения сверяет архивный артефакт с опубликованным хешем и берёт территорию, комплекты и лимиты из `history/<date>/dataset/common`. Отличающийся график, навыки, транспорт, старт или неизвестное изменение оснащения отклоняются. Пробелы и известный старый формат импорта нормализуются; сохранённые смены и версии не переписываются.
- Подбор, подтверждение и точный расчёт используют одинаковые нормализованные входы и отпечатки. Резервным специалистам не подставляются чужие смены или домашние координаты для искусственного допуска. Границы рейтинга сохраняются.
- На локальном стенде штатным установщиком подключён существующий комплект `weekly-rail-snapshots-2026-09-29.zip`. Сверены контрольные суммы. Для исторических дат используется явно обозначенный эталон соответствующего дня недели, а не выдуманное историческое расписание.

## Проверка

- Все **347 Node-тестов прошли**, `pnpm build` прошёл.
- Новый регрессионный тест воспроизводит старую дату при реестре, созданном позднее; проверяет появление штатных кандидатов, границы рейтинга, будущий найм, архивирование в текущем дне, неизменность записей и отказ при изменённых координатах.
- Те же исторические входы независимо приняты Python-проверкой `validate_rating_inputs` по исходному набору дня.
- Чтение и нормализация прошли для всех **182 дней** локального архива.
- В браузере выполнены подбор → подтверждение → точный расчёт для 14.08.2026, диапазон 4,2–5, весь пул. Результат: **26 предложено, 428 допустимых кандидатов, итоговый план READY / VALID, 24 инженера, 150/155 назначений**. В исходном плане было также 150/155; пять неназначенных заявок не скрываются.
- Полный расчёт проверен на отдельной копии базы. Рабочие смены, версии, факты, реестр и аварийные решения совпали с исходными. Сервер возвращён на рабочую базу.
