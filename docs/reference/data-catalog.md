# Каталог данных

## Входы и первичные источники

| Путь от корня | Назначение |
| --- | --- |
| `data/sources/` | Неизменённые требования, нормативы и обезличенные материалы организаторов |
| `data/original_extract/` | Первичное извлечение таблиц для сопоставления со входами |
| `data/dataset/` | Нормализованные заявки, состав, навыки, оборудование, правила и контрольные суммы |
| `data/object-complexity/` | Дополнение с переменными длительностями, его происхождение и отдельный набор |
| `data/fixtures/` | Отдельные неизменные входы и планы для регрессионных тестов |
| `data/screening/` | Быстрые матрицы поиска кандидатов |

Рабочий набор выбирается конвейером явно. Поисковая матрица не заменяет точную поездку. Наборы с `CHECKSUMS.sha256` проверяются побайтово; правила перевода строк находятся в `.gitattributes`.

## Маршрутизация

`data/runtime-bundle/manifest.json` описывает проверяемые части дорожного графа, SQL-экспорта транспортного индекса и оригинальных GTFS/метро-источников. `tools/install_runtime_bundle.py` сверяет их до установки в Docker volumes. Индекс маршрутизации создаётся отдельно от операционной базы.

`data/transit/` хранит происхождение индекса и недельный архив железнодорожных снимков. `data/traffic4cast/` содержит публичный профиль движения. Подробности и точность — в [описании данных](data.md), [маршрутизации](routing.md) и [лицензиях](../../THIRD_PARTY_LICENSES.md).

## Проверенные примеры

- `algorithm/artifacts/complexity/initial-exact.json` — основа с актуальной переменной длительностью, связанная с её входами.
- `algorithm/artifacts/current/` — базовые примеры для воспроизведения и регрессионных проверок.
- `algorithm/artifacts/tz3/home-starts/` — сжатые входы, проверенный план, набор и манифест домашнего сценария.
- `site/public/test-data/` — скачиваемые примеры импорта и интеграционных контрактов.

Сохранённый пример принимается только при совпадении входов и проверенных контрольных сумм. Он не заменяет новый расчёт произвольного набора.

## Аналитика и модель

`site/public/data/analytics-history.json` содержит 182 дня модельных сводок. Полный операционный архив хранится отдельно: график не восстанавливает исходные заявки, поездки или фактическое выполнение. Генераторы и проверки находятся в `site/scripts/` и `site/tests/`.

`site/models/demand-forecast-catboost.cbm` — обученная модель прогноза спроса; связанные публичные признаки и прогнозы находятся в `site/public/data/`. Результаты повторного обучения, логи и временные файлы в Git не добавляются.

## Рабочие данные

SQLite смен, отзывы пользователей, факты, резервные копии, транспортные кэши и новые расчёты создаются во время работы. Они хранятся в постоянных Docker volumes либо игнорируемых локальных каталогах. Для переноса пользовательской истории нужна согласованная резервная копия, а не копирование аналитических сводок.
