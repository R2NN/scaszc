# Связь интерфейса и планировщика

## Поток данных

Импорт и ручной ввод передают заявки и инженеров Node API. Сервер готовит нормализованный вход и актуальные снимки длительности, запускает Python с OR-Tools, получает детальные поездки и независимый результат проверки. Интерфейс показывает назначение, порядок, времена и причины очереди; опубликованная версия сохраняется транзакционно в SQLite.

Контрольная операционная основа 17.08.2026 содержит 203 назначенные заявки из 205, срочные 15/15 и 34 используемых инженера. Данные, модель длительности и домашний сценарий имеют отдельные контрольные суммы. Успешный план другого набора не подменяет текущий результат.

## Барьер публикации

Необходимы `status=EXACT_VALID`, `publicationAllowed=true`, `validation.status=VALID`, контрольная сумма и отсутствие приблизительных поездок. Поисковая матрица служит только поиску. Новый адрес требует настоящего ответа маршрутизатора; неизвестные координаты и поездки не восстанавливаются эвристической прямой линией для публикации.

`site/server/shiftStore.mjs` проверяет результат перед записью. Исходная версия, черновик и факт сохраняются раздельно. Перепланирование начинается от опубликованного плана и текущего состояния; уже выполненная или начатая часть защищена.

## Основные модули

| Контур | Реализация |
| --- | --- |
| Приём и хранение операций | `site/server/operationsApi.mjs`, `shiftStore.mjs` |
| Первичный расчёт | `site/scripts/exact-plan-runner.mjs`, инструменты `algorithm/tools/` |
| Событийный расчёт | `site/scripts/exact-replan-runner.mjs`, `algorithm/tools/replan_ui_event.py` |
| Ограничения и проверка | `algorithm/src/beeline_planning/` |
| Точный транспорт | `algorithm/src/beeline_routing/` и локальный runtime |

Общие правила — в [планировании](planning.md). Один API-процесс выполняет один тяжёлый расчёт одновременно; просмотр продолжается. Для воспроизведения используйте [полный запуск](../operations/quickstart.md) и [команды проверок](../development/contributing.md).

## Дополнительные расчётные пути

[Подбор состава](rating-workflow-and-planning.md) использует `staffingPlanning.mjs` и `plan_staffing.py`: предложение людей подтверждается до запуска проверки маршрутов. Рейтинг готовых маршрутов обслуживает отдельный `plan_by_rating.py`.

[Длительность](../features/work-duration.md) рассчитывается в Node API до подготовки входа Python. Снимок включает модель, состав работ, подтверждённые измерения и итоговые минуты. Начатые визиты сохраняют исходный снимок при событиях; будущие получают актуальную оценку по правилам события.

[Сеть](../features/network-context.md) хранит общие неисправности и явные зависимости. Действие переноса открывает изменение клиентского окна; расчёт и публикация идут через операционный API. Схема компонентов — в [архитектуре](architecture.md), запросы — в [справочнике API](api.md).
