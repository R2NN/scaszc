## Запрос от браузера до расчёта

React/Vite отображает списки, формы, аналитику и одну постоянную MapLibre-карту. [main.mjs](../../site/server/main.mjs) отдаёт `dist/client`, передаёт `/api` сначала операционным обработчикам, затем первичному планировщику и worker-адаптеру. На VM внешний Nginx проксирует запросы в приложение на `127.0.0.1:8787`.

| Компонент | Ответственность | Основные модули |
| --- | --- | --- |
| Смена | Опубликованный план, черновик, ревизии, факты, PDF и бюджет AI | `operationsApi.mjs`, `shiftStore.mjs` |
| Начальный план | Нормализация длительности, сохранённый проверенный результат либо новый Python-запуск | `exactPlanningApi.mjs`, `exact-plan-runner.mjs` |
| Длительность и паспорт | Норматив, состав работы, история, обратная связь, условия обслуживания и снимок оценки | `complexityApi.mjs`, `complexityStore.mjs`, `durationModel.mjs`, `engineerFeedback.mjs` |
| Рейтинг | Отзывы исполнителю, разборы, версия оценок, предложение и расчёт состава | `ratingApi.mjs`, `ratingStore.mjs`, `staffingPlanning.mjs` |
| Авария | Серверные часы, текущее положение, предложения, подтверждение выбранного инженера | `dispatchApi.mjs`, `emergencyDispatch.mjs` |
| Проезд | Каталог, ручное перекрытие, совместный расчёт ограничений и аудит пути | `transportApi.mjs`, `transportScenario.mjs`, `transportScope.mjs` |
| Сетевой контекст | Узлы, явные связи с заявками, статус восстановления и решения по выездам | `serviceContextApi.mjs`, `serviceContextDomain.js` |

Серверные модули находятся в `site/server/`, запуск расчётных процессов — в `site/scripts/`, общие интерфейсные контракты — в `site/src/`. Сеть помогает подготовить изменение окна; подтверждение статуса узла само по себе не меняет назначение.

## Хранение и артефакты

SQLite с WAL хранит рабочие записи транзакционно. `plan_versions`, события и факты связаны с операционной сменой; `rating_*` — с оценками и подбором состава; `service_contexts` — с сетевыми зависимостями. Полный перечень таблиц задают схемы в серверных хранилищах.

`runtime/ui-runs`, `runtime/exact-replans` и кэши дороги содержат входы, транспортные доказательства и результаты Python. Сохранённый план связан с `contentSha256`; следующий пересчёт использует соответствующий исходный артефакт. Код релиза, изменяемая база и установленные дорожные данные имеют разные каталоги и сроки жизни. Упакованные входы проверяются по SHA-256.

## Вычислительные процессы

[planningSlot.mjs](../../site/server/planningSlot.mjs) предоставляет один общий тяжёлый слот в процессе API. Его используют начальный расчёт, перепланирование, рейтинг и оперативные проверки. Чтение и навигация продолжают работать. Занятый слот отражается в ответе API; транспортный сценарий умеет повторять ожидание. Каждый worker имеет бюджет, прогресс и освобождение ресурсов при завершении, ошибке или отмене.

Python использует OR-Tools для первичного поиска, событийный поиск для будущей части смены и независимый валидатор для результата. Дороги рассчитывает локальная Valhalla; транспортный индекс объединяет GTFS, МЦК/МЦД и метро. [Схема алгоритма](planning.md) показывает три пути расчёта.

## Внешние сервисы

Geoapify предоставляет адресные подсказки и геокодирование через сервер. Yandex AI Studio отвечает по ограниченному снимку смены, с серверными лимитами запросов и токенов. PDF создаётся из сохранённого плана без обращения к AI. Ключи передаются через окружение API. Для дорожного Geoapify-провайдера требуется отдельная явная настройка `GEOAPIFY_ROUTING_API_KEY`.

Вход пользователя и разграничение прав — следующий этап эксплуатации: текущее поле `actor` фиксирует автора действия, а профиль задаёт отображаемое имя. Подготовка доступа и HTTPS описана в [эксплуатации](../operations/deployment.md).
