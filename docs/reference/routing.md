# Локальная маршрутизация

Рабочий провайдер `valhalla-local-transit` сочетает дорожный граф Valhalla с локальным индексом общественного транспорта. Массовый расчёт контрольного сценария не требует платных дорожных запросов. Адаптеры других провайдеров сохранены в Python как заменяемые реализации и включаются отдельно.

## Данные поездки

| Участок | Расчёт |
| --- | --- |
| Автомобиль, велосипед, пешком | Valhalla по существующим дорогам OSM |
| Автобус/трамвай | GTFS, календарь и фактические отправления сохранённого источника |
| МЦК/МЦД и охваченные пригородные направления | Недельные эталонные снимки отправлений |
| Метро | Каталог перегонов и переходов, часы работы, вход/выход и модель ожидания |

Ожидание метро по умолчанию — 180 секунд на посадку. Оно сохраняется в индексе и отмечается в provenance; это параметр модели, а не вымышленная запись отправления. Для железной дороги берётся соответствующий день недели из установленного набора. Дата источника и сценарная дата различаются явно.

Для короткой поездки сравнивается прямой пеший путь. Смешанные варианты могут включать наземный транспорт, метро и железную дорогу. Пешеходные подходы рассчитываются по дорогам. Транспортная геометрия между остановками может быть схематической; она не выдаётся за обследованную траекторию рельсов.

## Точность и ограничения

Поиск кандидатов использует матрицы и нижние оценки; итоговая последовательность рассчитывается с конкретными временами отправления. После каждой работы меняется следующий момент выезда. Раннее прибытие допускает ожидание окна, позднее начало или окончание после смены отклоняются.

Закрытие проверяется на фактическом направленном ребре и времени прохождения. Метро учитывает движение, входы, пересадки, часы работы и ожидание известного открытия. Независимый аудит повторяет эти условия для выбранного пути. `UNKNOWN` означает недостаточность данных либо исчерпание поиска, а не доказанную невозможность поездки.

Кэш хранит ответ вместе с режимом, входами и происхождением. Он ускоряет повторные запросы, но не разрешает заменить путь прямой линией или применить результат другой версии сети. Все новые адреса и изменённые ограничения проходят обычный расчёт.

## Установка и воспроизведение

[Полный Compose-запуск](../operations/quickstart.md) устанавливает дорожный граф, транспортный индекс и исходники по SHA-256. `data/runtime-bundle/manifest.json` хранит размеры и происхождение. Недельный архив устанавливает `algorithm/tools/install_weekly_rail_snapshots.py`.

Для CLI из корня, после установки runtime и зависимостей:

```bash
PYTHONPATH=algorithm/src python -m beeline_routing route \
  --provider valhalla-local-transit \
  --dataset data/dataset --scenario core \
  --origin-id LOC-0001 --destination-id LOC-0002 \
  --mode PUBLIC_TRANSIT \
  --departure-at 2026-08-17T09:00:00+03:00 \
  --transit-index data/transit/moscow_2026-08-17.sqlite \
  --cache runtime/routes.sqlite3 --output runtime/route-example.json
```

ID точек берутся из `data/dataset/common/locations.csv`; значения выше служат формой команды. Адрес Valhalla задаётся `VALHALLA_ROUTE_ENDPOINT`. В контейнерной поставке эти настройки уже установлены. Дополнительные параметры доступны через `python -m beeline_routing route --help` с тем же `PYTHONPATH`.

Для пересборки индекса из собственных источников используется `algorithm/tools/build_local_transit_index.py`; сохраните календарь, время ожидания, provenance и новые контрольные суммы. Для регулярного обновления внешних расписаний нужны собственные ключи; не выводите их в журнал.

## Основные модули

`algorithm/src/beeline_routing/` содержит адаптеры, `local_transit.py`, `oracle.py`, кэш и экспорт. `algorithm/tools/transport_network.py` обслуживает геометрию ручных ограничений. `runtime/` содержит конфигурацию и запуск Valhalla.
