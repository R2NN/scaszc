# Полная версия BeeGo: новый компьютер

Ветка: **codex/beego-complete-runtime**. Она включает все изменения из `codex/port-object-building-model` и полный комплект ресурсов для реального аварийного расчёта.

## Почему прошлый запуск не показывал кандидатов

Предыдущая инструкция проверяла установку интерфейса, а не аварийный расчёт с отсутствующими внешними ресурсами. Чистый запуск воспроизвёл ошибку `не найден исходный файл ... gtfs-inspect`. На рабочем стенде уже был локальный транспортный индекс. В этой ветке добавлены проверяемые части дорожного графа, оригинальные GTFS/метро-источники и SQL-экспорт публичного транспортного индекса. Рабочая SQLite, ключи и история пользователей не копируются.

## Запуск одной командой

Нужны **Git и запущенный Docker с Docker Compose** (на Windows — Docker Desktop с Linux-контейнерами). Node и Python устанавливаются внутри образа. Потребуются интернет для скачивания образов и зависимостей и примерно 15 ГБ свободного места. Дополнительные ресурсы в Git занимают около 459 МБ; Git LFS и ручное копирование данных не нужны.

```bash
git clone --branch codex/beego-complete-runtime --single-branch https://github.com/R2NN/scaszc.git BeeGo-complete
cd BeeGo-complete
docker compose -f compose.complete.yaml up --build -d
```

Открыть **http://127.0.0.1:8787/**. Первый запуск распаковывает и проверяет ресурсы, собирает образ и создаёт новую базу с контрольной сменой. Не закрывайте Docker Desktop. Существующие рабочие базы не удаляются; у этого комплекта отдельные именованные volumes. Дорожный граф и транспортный индекс дополнительно размещаются в Linux volumes Docker: это исключает медленное чтение SQLite/mmap через папку Windows. Их копии сверяются по SHA-256; история пользователей в этот перенос не входит.

```bash
docker compose -f compose.complete.yaml ps
docker compose -f compose.complete.yaml logs --tail=40 runtime-setup valhalla app
```

Контейнер `runtime-setup` должен завершиться с кодом 0; `valhalla` и `app` — стать healthy. Проверить готовность именно расчёта: открыть `http://127.0.0.1:8787/api/runtime/readiness` — требуется `ready: true`, а не только HTTP 200 от главной страницы. Если 8787 занят другим приложением, задайте свободный `BEEGO_HTTP_PORT` в окружении перед запуском; не останавливайте чужие процессы.

## Проверка аварии

Откройте «Ход смены → Аварии → Запустить сценарий с 06:00». Поставьте время 11:17. Дождитесь проверенных карточек, выберите инженера и нажмите «Направить на аварию». Первый расчёт с пустым кэшем может занимать несколько минут: он измеряет реальные дороги и пересадки. Повторные проверки используют накопленный кэш; выдавать вымышленные маршруты ради скорости система не будет. Автовыбор можно отключить в настройке для ручной проверки.

Без собственных ключей работают контрольный аварийный сценарий, маршрутизатор, сохранённые расписания, основные разделы и схема здания. AI, поиск произвольного адреса через внешний геокодер и обновление внешних расписаний требуют собственных ключей. Клиентские планы/история прежнего устройства не входят в публичную ветку.

## Обновление и остановка

```bash
git pull --ff-only
docker compose -f compose.complete.yaml up --build -d
```

Остановка: `docker compose -f compose.complete.yaml stop`. Не применяйте `down -v`, если нужно сохранить базу и кэш.

## Границы комплекта

Используются настоящий Valhalla 3.8.3, прежние алгоритмы и независимая проверка плана. Данные внутри здания по-прежнему явно демонстрационные, пока не импортирован обследованный план. Дорожные/транспортные исходники сохраняют происхождение и условия их источников; см. `data/runtime-bundle/manifest.json` и `THIRD_PARTY_LICENSES.md`.
