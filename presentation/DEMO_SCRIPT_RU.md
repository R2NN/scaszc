# Показ BeeGo! за 5–7 минут

1. **Набор дня.** Открыть сайт и назвать три участка, общее число заявок и дату. Показать, что исходные заявки могут поступать из CSV/JSON; полный импорт демонстрировать только если есть время.
2. **План.** Показать статус 205/205, 32 активных маршрута и 0 заявок для ручного разбора. Открыть одну бригаду, пройти по порядку остановок и показать время прибытия, начало работы и километраж.
3. **Объяснение.** Открыть заявку и показать навык, транспорт, временное окно и краткое пояснение назначения. Уточнить, что окно относится к прибытию и началу, а работа должна завершиться внутри смены.
4. **Авария.** Добавить контрольную срочную заявку через экран перепланирования. Показать новый проверенный план 206/206, изменения по маршрутам и приоритет аварии. Если офлайн-маршрутизатор на стенде недоступен, использовать заранее подготовленную запись этого шага; не обещать живой пересчёт до проверки сервера.
5. **Сравнение.** Открыть аналитику: число бригад и пробег по каждому маршруту и итогу. Показать FCFS 101/205 отдельно от точного 205/205 и прямо пояснить разницу в покрытии.
6. **Завершение.** Назвать ограничение прототипа: новый день зависит от маршрутизатора и расписаний; сервер публикует результат только после независимой проверки. Показать README и инструкцию стенда при вопросах по воспроизведению.

Перед защитой пройти все шаги на том же домене и браузере, на которых будет показ. Убедиться, что карта загружается и внешние ключи настроены только там, где они действительно нужны.
