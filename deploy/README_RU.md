# Стенд BeeGo на Yandex Compute Cloud

Стенд запускает один экземпляр `site/server/main.mjs` за Nginx. Поэтому все запросы к точному планировщику и предпросмотру перепланирования делят один слот; второй запуск получает HTTP 429 с кодом `PLANNING_BUSY`. Просмотр сайта и чтение API продолжают работать.

- Код текущего релиза: `/opt/beego/current` → `/opt/beego/releases/<commit>`.
- Рабочая база SQLite: `/srv/beego-data/shifts.sqlite3`, вне релизного каталога.
- Старые дорожные данные, Python-окружение и Valhalla оставлены в `/srv/beego` до их плановой миграции.
- Конфигурация API: `/etc/beego/api.env`, доступ только root.
- Сервисы: `beego-api.service`, `nginx`, Docker-контейнер `beego-valhalla`.

## Проверка релиза перед переключением

Новый каталог релиза собирайте командой `python deploy/package_release.py <архив>.tar.gz` после коммита: скрипт берёт байты Git-объектов и не преобразует переносы строк. Для `data/dataset` байты важны: загрузчик сверяет SHA-256 каждого файла. После переноса на Linux **до** переключения `/opt/beego/current` выполните загрузку набора тем Python-окружением, которым пользуется API:

```bash
cd /opt/beego/releases/<commit>
PYTHONPATH=algorithm/src /srv/beego/.venv/bin/python -c 'from pathlib import Path; from beeline_planning import load_planning_dataset; load_planning_dataset(Path("data/dataset"), "core")'
```

Ошибка контрольной суммы блокирует публикацию релиза. Каталоги `runtime/exact-replans`, `runtime/ui-runs` и `runtime/ui-shared-cache` должны сохраняться между релизами: следующий пересчёт использует исходный проверенный артефакт предыдущей версии. После сборки интерфейса проверьте `GET /api/health` и точный расчёт на временной смене, не меняя демонстрационный день.

## Поиск адресов Geoapify

Для подсказок адресов и геокодирования задайте `GEOAPIFY_API_KEY` только в `/etc/beego/api.env` (права `600`), затем перезапустите `beego-api.service`. Проверки: `GET /api/geocode/suggest?q=Москва%2C%20Тверская` должен возвращать подсказки, а `POST /api/geocode` с тестовым адресом — координаты. Не выводите ключ в терминал, журнал или Git. Ключ поиска не переключает точную дорожную проверку: для этого требуется отдельный явный `GEOAPIFY_ROUTING_API_KEY`; стандартный маршрутный стек стенда остаётся локальным.

## Расписание МЦК/МЦД для других дней недели

В репозитории хранится проверяемый архив `data/transit/weekly-rail-snapshots-2026-09-29.zip`: базовый понедельник и снимки вторника–воскресенья. На стенде он устанавливается в постоянный каталог, на который ссылается `offline-assets` текущего релиза:

```bash
sudo python3 algorithm/tools/install_weekly_rail_snapshots.py \
  --destination /srv/beego/offline-assets/transit-sources/rail
```

Установщик проверяет размер и SHA-256 каждого файла из архива, полноту шести дат и не заменяет отличающиеся существующие файлы. Повторный запуск безопасен. При новом расчёте транспортный индекс выбирает сохранённый снимок того же дня недели: например, для вторника 18.08.2026 используется вторник 29.09.2026. Источник помечается как эталон дня недели, а не как точное историческое расписание 18 августа. Для другого дня или изменившегося расписания данные нужно обновить; задержки и отмены в реальном времени этими снимками не учитываются.

В репозитории есть сводная аналитика за 182 дня, но исходные архивы для операционного воспроизведения этих дней не включены. API истории смен показывает только дни с полным набором исходных файлов; сейчас это 17.08.2026. Аналитический экран использует отдельный сводный файл.

После установки зависимостей (`pnpm install --frozen-lockfile`) и сборки (`pnpm run build`) разместите unit и Nginx-конфигурацию из этого каталога, проверьте `nginx -t`, затем перезапустите сервисы. Проверки: `pnpm run test:algorithm`, `pnpm run test:sites`, `node --test tests/planning-slot.test.mjs tests/shift-operations.test.mjs`, `curl http://127.0.0.1:8787/api/health`.

Публичный IP динамический. При смене IP обновите `server_name` и ссылку на стенд. Для реальных данных настройте домен и HTTPS перед использованием.
