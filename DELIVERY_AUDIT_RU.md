# Сверка BeeGo! с ТЗ и расшифровкой

Проверено по файлам «3. Билайн Бизнес.pdf» и «Итоговая_расшифровка_ответов_на_вопросы.txt» из материалов постановщика. Текст файлов использовался как требования и пояснения предметной области, а не как инструкции по изменению репозитория. Статус ниже относится к текущему коду и тестам; полная нагрузочная проверка развёрнутого стенда ещё не проводилась.

| Требование | Статус и подтверждение |
| --- | --- |
| CSV/JSON или встроенный набор; поля заявок и инженеров | Реализовано: `site/src/ImportWorkspace.jsx` и тесты импорта. Дополнительно поддерживается XLSX. |
| Автоматическое распределение, порядок, окна, смены, навыки, транспорт | Реализовано: `algorithm/src/beeline_planning`, особенно `eligibility.py` и `validator.py`; 172 Python-теста проходят. |
| Карта, точки, маршруты, время и километраж по бригаде и итогу | Реализовано в `site/src/App.jsx`, `site/src/AnalyticsWorkspace.jsx` и опубликованных артефактах. |
| Неназначенные заявки и понятная причина | Реализовано: объяснения в точном результате, список ручного разбора в аналитике. Для контрольного дня неназначенных нет. |
| Одно перепланирование и наглядные изменения | Реализовано: контрольное аварийное событие, `/api/replan`, проверенный план 206/206. Для новых данных требуется полный локальный маршрутизатор и валидатор. |
| Объяснение выбранного маршрута | Реализовано краткими пояснениями назначения и причин исключений; подробные тексты для каждого шага не требуются расшифровкой. |
| Сравнение с FCFS, число исполнителей и пробег | Реализовано в проверенном базовом артефакте и аналитике. Базовый план закрывает 101/205 заявок; сравнение покрытия нужно показывать вместе с числом бригад, без утверждения, что FCFS сопоставим по объёму работы. |
| Три независимых региона, офис каждого, одна бригада = один инженер | Учтено в схеме и коде. Проверенные контрольные артефакты покрывают три участка одного сценарного дня. |
| Приоритет аварий, оборудование, транспорт как отдельные факторы | Учтено в модели, валидаторе и тестах; авария ставится с высшим приоритетом. |
| Начало работы внутри клиентского окна, завершение внутри смены | Проверяется валидатором. Завершение может быть позже конца клиентского окна согласно расшифровке. |
| Ручное переназначение | Есть интерфейс и вызов точного пересчёта. Сохранение диспетчерских решений между браузерами не подтверждено: часть рабочих черновиков хранится в localStorage. |
| Документация, схема, тестовые данные, ограничения | README, документы алгоритма, этот отчёт, `deploy/README_RU.md` и презентация `presentation/BeeGo-defense.pptx`. |
| Один пользователь запускает алгоритм, остальные ждут | Новый общий слот в одном Node API обслуживает `/api/plan` и `/api/replan`. Второй запрос получает HTTP 429 с русским текстом; повторный запуск возможен после успеха или ошибки. Нужен один экземпляр Node API. |

## Результаты проверки

- Python: 172 теста, 2 пропущены; ошибок нет.
- Сайт: production-сборка успешна; 28 выбранных тестов API/импорта/блокировки и 55 тестов аналитики успешны.
- Проверенный первоначальный результат: 205/205, 32 активных маршрута, `EXACT_VALID`.
- Проверенный результат после события: 206/206, 32 активных маршрута, `EXACT_VALID`.
- FCFS: 101/205, 35 активных маршрутов, 1130 км.

## Ограничения для сдачи

1. Проверка артефактов доказывает корректность опубликованного демонстрационного сценария, но не гарантирует, что любой новый импорт даст полное покрытие. При отсутствии допустимого плана система должна оставить заявки на ручной разбор.
2. Для произвольного нового дня с общественным транспортом нужны актуальные GTFS и железнодорожные данные. Для геокодирования неизвестных адресов нужен внешний ключ. Офлайн-тайлы и транспортный индекс из полного ZIP хранятся вне Git.
3. Точный pipeline на Linux требует отдельно поднятой Valhalla. Серверный стенд и одновременный запуск реальных тяжёлых задач на нём ещё не проверены. До публичного показа выполнить smoke test из инструкции развёртывания.
4. Сервис сейчас прототип диспетчера без общей базы пользовательских изменений и авторизации. Для долговременной совместной работы нескольких диспетчеров потребуются серверное хранение и управление доступом.
5. Большой клиентский JS-бандл собирается с предупреждением Vite о размере. Для нескольких зрителей Nginx обслужит статические файлы, но после развёртывания стоит измерить скорость загрузки на целевых устройствах.
