# BeeGo!: переносимый комплект

Этот комплект содержит интерфейс BeeGo!, локальный API, Worker, опубликованные точные планы, тестовые данные, готовую веб-сборку и исходный пакет алгоритма планирования.

## Быстрый запуск сайта на новом компьютере

1. Установите [Node.js 20 LTS или новее](https://nodejs.org/).
2. Полностью распакуйте общий ZIP-архив в обычную локальную папку.
3. Откройте папку `beeline-route-planner`.
4. Нажмите правой кнопкой на `START_SITE.ps1` и выберите запуск через PowerShell.
5. Если Windows запрещает запуск сценария, откройте PowerShell в этой папке и выполните:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\START_SITE.ps1
```

При первом запуске сценарий выполнит `npm ci`, затем откроет локальный API и интерфейс в двух окнах PowerShell. Сайт будет доступен по адресу:

```text
http://127.0.0.1:4174/
```

Локальный API работает по адресу `http://127.0.0.1:8787/`. Не закрывайте два окна PowerShell, пока пользуетесь сайтом.

## Ручной запуск

Из папки `beeline-route-planner`:

```powershell
npm ci
npm run dev:api
```

Во втором окне PowerShell:

```powershell
npm run dev -- --host 127.0.0.1 --port 4174
```

## Ключ Geoapify

Сайт, карта, готовые планы и тестовый сценарий запускаются без секретного ключа. Ключ нужен только для геокодирования новых адресов.

1. Скопируйте `.dev.vars.example` в `.dev.vars`.
2. Замените `your_free_geoapify_key` на собственный ключ Geoapify.
3. Перезапустите локальный API.

Секретный `.dev.vars` специально не включён в переносимый архив, чтобы ключ нельзя было случайно опубликовать вместе с проектом.

## Проверочный сценарий интерфейса

1. Откройте раздел импорта.
2. Загрузите `public/test-data/beego-algorithm-initial.json`.
3. Нажмите «Загрузить 205 заявок и 35 инженеров».
4. Нажмите «Спланировать» и затем «Построить план».
5. Интерфейс должен показать 200 назначений и 5 неназначенных заявок.
6. Кнопка «Новая авария» добавляет событие `EAST-EVENT-001`; событийный план содержит 201 назначение и 5 неназначенных заявок.

Готовый событийный набор находится в `public/test-data/beego-algorithm-integration.json`.

## Полный исходный алгоритм

Рядом с папкой сайта находится `LCT2_ALGORITHM_UI_HANDOFF_FINAL_2026-09-17.zip`. Это полный исходный пакет алгоритма: Python-код планирования и маршрутизации, OR-Tools, тесты, готовые планы, исходные данные, локальные транспортные индексы и данные Valhalla.

Для полного запуска алгоритма:

1. Распакуйте этот вложенный ZIP отдельно. После распаковки потребуется около 4 ГБ свободного места.
2. Установите Python 3.12+ и Docker Desktop.
3. Откройте `LCT2_ALGORITHM_UI_HANDOFF/INTEGRATION_HANDOFF.md` и выполняйте раздел «Быстрый старт».

Основные команды из исходной инструкции:

```powershell
python -m pip install -e .
powershell -ExecutionPolicy Bypass -File handoff_assets\start_valhalla.ps1
powershell -ExecutionPolicy Bypass -File handoff_assets\verify_package.ps1
```

Для чтения архитектуры алгоритма используйте документы в таком порядке:

1. `INTEGRATION_HANDOFF.md`
2. `INTERFACE_API_CONTRACT.md`
3. `NEW_DATA_RUNBOOK.md`
4. `algorithm_spec_draft.md`
5. `routing_README.md`

## Что находится в комплекте

- `src/` — исходники React-интерфейса;
- `worker/` — backend-обработчики API;
- `scripts/` — локальный API, подготовка артефактов и проверки интеграции;
- `public/data/beego-exact-plans.json` — опубликованные точные планы для интерфейса;
- `public/test-data/` — контрольные наборы;
- `public/` — изображения, шаблоны импорта, карта и геоданные;
- `dist/` — готовая production-сборка;
- `docs/` — архитектура интеграции и требования;
- `tests/` — тесты Worker;
- `package.json` и `package-lock.json` — зафиксированные зависимости Node.js;
- `LCT2_ALGORITHM_UI_HANDOFF_FINAL_2026-09-17.zip` — полный исходный алгоритм и офлайн-данные.

`node_modules`, временные кадры видео, локальные кэши разработки и Git-история в архив не включены. `node_modules` восстанавливается точной командой `npm ci` из lock-файла и не должен переноситься между компьютерами.
