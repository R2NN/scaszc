# BeeGo!: переносимый комплект

Полный ZIP содержит текущий frontend, backend, production-сборку, новый точный планировщик, модели, историческую аналитику, данные, офлайн-Valhalla, GTFS и схему метро. После распаковки структура каталогов должна сохраниться.

## Запуск на новом компьютере

1. Установите Node.js 20 LTS или новее.
2. Распакуйте архив в локальную папку с правом записи.
3. Откройте PowerShell в корне распакованного проекта.
4. Выполните:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\START_SITE.ps1
```

Адреса после запуска:

- сайт: `http://127.0.0.1:5173/`;
- API: `http://127.0.0.1:8787/api/health`.

## Что не входит

- `node_modules` — восстанавливается точной командой `npm ci`;
- `.git` — не требуется для запуска;
- `.dev.vars` — может содержать секрет; создаётся по `.dev.vars.example`;
- кэши и временные журналы.

## Полный алгоритм

Для просмотра сайта Python и Docker не нужны. Для пересчёта новых наборов установите Python 3.12+ и прочитайте `AGENT_STARTUP_RU.md`, `algorithm/NEW_DATA_RUNBOOK.md` и `algorithm/routing_README.md`. Папка `valhalla-data` уже содержит совместимые офлайн-данные Valhalla 3.8.3.

Если в новом наборе есть бригады на общественном транспорте, сайт автоматически строит индекс расписания для даты набора и сохраняет его в `runtime/ui-shared-cache/transit`. Исходники `offline-assets/transit-sources/gtfs`, `offline-assets/transit-sources/rail` и `offline-assets/transit-sources/metro/schema.json` уже лежат в полном ZIP; диск `A:` после распаковки не нужен. При замене источников их расположение можно задать переменными `BEEGO_GTFS_DIR`, `BEEGO_RAIL_DIR` и `BEEGO_METRO_SCHEMA`. На другие дни недели, кроме понедельника, доступное эталонное железнодорожное расписание не переносится: индекс содержит рейсы из GTFS и отдельно обозначенную модель метро. Если GTFS не содержит рейсов на выбранную дату, потребуется более свежий GTFS: упаковка исходного набора не создаёт отсутствующие рейсы.

## Сборка полного ZIP

Из текущего репозитория выполните `python site/scripts/build-portable-archive.py --output BeeGo_FULL_TRANSFER.zip`. Сборщик берёт исходники из указанных выше каталогов, а при их отсутствии — из локального каталога `A:/LCT2-routing`. Для другого расположения используйте `--gtfs-dir`, `--rail-dir`, `--metro-schema` и `--valhalla-dir`. При отсутствии хотя бы одного обязательного файла сборка прерывается до создания ZIP. Исходники входят внутрь ZIP, поэтому на компьютере получателя эти пути и параметры не нужны.

## Контроль целостности

Внутри архива находится `PACKAGE_MANIFEST_SHA256.tsv`. Рядом с ZIP лежит файл `<имя>.zip.sha256` для проверки самого архива.
