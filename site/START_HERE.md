# BeeGo! — полная передача проекта на 22 сентября 2026

Это самодостаточный комплект текущей версии BeeGo!. В корне находятся сайт, backend, точный алгоритм, модели, данные, офлайн-маршрутизатор и инструкции. Отдельной папки `site` внутри комплекта нет: корень архива и есть корень веб-проекта.

## Зафиксированный результат

- Исходный набор: **205 из 205 заявок, 28 бригад**, статус `EXACT_VALID`.
- С контрольной аварийной заявкой: **206 из 206 заявок, 28 бригад**, статус `EXACT_VALID`.
- В интерфейсе используется новый проверенный артефакт `public/data/beego-exact-plans.json`.
- Аналитическая история объединяется с загруженной сменой, а не заменяется ею.
- ML-прогноз хранится в `models/` и `public/data/`.

## Запуск сайта

На Windows установите Node.js 20+, распакуйте ZIP и из корня выполните:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\START_SITE.ps1
```

После успешной проверки откроется `http://127.0.0.1:5173/`. Backend также доступен по `http://127.0.0.1:8787/api/health`.

## Основные каталоги

- `src/`, `public/`, `worker/`, `scripts/` — frontend, API и интеграция;
- `algorithm/` — Python-ядро планирования, CLI, тесты и артефакты;
- `data/` — входные датасеты, screening-матрицы и транспортный индекс;
- `runtime/` — локальный мост Valhalla и кэш точных запросов;
- `valhalla-data/` — полный офлайн-runtime, тайлы и OSM PBF;
- `models/` — CatBoost-модель;
- `source_materials/` — исходные материалы задачи;
- `tests/` — тесты сайта, API, аналитики и перепланирования;
- `dist/` — готовая production-сборка.

`node_modules` не переносится и восстанавливается командой `npm ci`. `.dev.vars` исключён, потому что может содержать секретный ключ; используйте `.dev.vars.example`.

## Полный алгоритм для новых данных

Для просмотра сайта и использования опубликованных планов Python и Valhalla не нужны. Для точного пересчёта ранее неизвестных адресов дополнительно требуются Python 3.12+, зависимости из `algorithm/pyproject.toml` и реальный Valhalla 3.8.3. Локальный runner перед расчётом проверяет и при необходимости запускает совместимый мост командой `python algorithm/tools/ensure_local_valhalla.py`; если маршрутизатор не готов, план не подменяется оценкой и не публикуется.

После импорта нового набора кнопка «Построить план» создаёт отдельный набор по схеме 2.1.0 и запускает полный exact pipeline. Результат принимается только при `EXACT_VALID` и независимом `VALID`. Автомобильные, пешие и велосипедные смены можно рассчитывать на указанную дату; для общественного транспорта нужен локальный индекс расписания на ту же дату. Координаты заявок должны быть подтверждены, а старт инженера задан координатами либо известным офисом. Остатки общего оборудования для нового участка обязательно вводятся в окне планирования; для известных участков показаны подтверждённые количества из исходного набора, которые можно изменить для текущего расчёта. Изменения передаются в `sharedInventory`.

В «Аналитика → Ресурсы» ручное назначение передаёт выбранную пару в точный пересчёт. Если жёсткое закрепление невозможно, план не меняется. Там же журнал снятия бригад со смены хранит черновик, подтверждение, отметку передачи и отмену в браузере; реальной интеграции с кадровой системой нет.

Начинайте с:

1. `AGENT_STARTUP_RU.md`;
2. `HANDOFF_INTEGRATION_GUIDE.md`;
3. `algorithm/NEW_DATA_RUNBOOK.md`;
4. `algorithm/routing_README.md`.

## Проверка целостности

Рядом с ZIP создаётся файл `.sha256`, а внутри архива — `PACKAGE_MANIFEST_SHA256.tsv` с SHA-256 каждого включённого файла.
