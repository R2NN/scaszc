# BeeGo: перенос интерфейса и локального API

Этот комплект предназначен для передачи текущего интерфейса на другой ПК и последующего подключения **нового** алгоритма маршрутизации. В нём сохранены вкладки, стили, анимации, всплывающие окна, изображения, шаблоны Excel, локальный API, тесты и снимок текущей SQLite-базы. Старый Python/Valhalla-стек, его тайлы и обучающие модели **не включены**. Запускать их на новом ПК не нужно.

## Быстрый запуск на Windows

1. Распакуйте ZIP в обычную папку, например `C:\BeeGo\BeeGo_INTERFACE_TRANSFER`. Не запускайте проект изнутри ZIP.
2. Установите Node.js 22 или новее (вместе с npm), Windows x64/arm64. Для первой установки зависимостей нужен интернет.
3. Откройте PowerShell в распакованной папке и выполните:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\START_INTERFACE.ps1
   ```

   Первый запуск вызовет `npm ci --ignore-scripts` по зафиксированному `package-lock.json`. Это важно: пакет SQLite уже содержит готовые бинарные модули для Windows; обычный `npm ci` на некоторых ПК пытается компилировать модуль и требует Visual Studio C++. После установки откроется `http://127.0.0.1:5175/?date=2026-08-17`. Локальный API доступен по `http://127.0.0.1:8787/api/health`. Дата 17.08.2026 выбрана для демонстрационного снимка; другую дату можно выбрать в интерфейсе.
4. Чтобы остановить процессы, выполните `powershell -ExecutionPolicy Bypass -File .\STOP_INTERFACE.ps1`.

Порты 5175 и 8787 должны быть свободны. Журналы процессов — в `.beego-run`. Если первый запуск завершился ошибкой, смотрите `api-error.log` и `frontend-error.log`. Проверка установки: `node --version`, `npm --version`. На ПК без доступа к npm заранее подготовьте локальный кэш npm; `node_modules` в ZIP намеренно не вложен, чтобы избежать несовместимых бинарных модулей между системами/архитектурами. Для macOS/Linux: `npm ci --ignore-scripts`, затем `npm run build` и `npm run start:server`; приложение откроется на `http://127.0.0.1:8787`. Готовые бинарные модули SQLite в npm-пакете существуют также для этих систем, но данный ZIP проверен на Windows.

На Windows 10/11 интерфейс использует системный Segoe UI (если установлен Inter, он выбирается первым). Шрифт из интернета не подгружается. Остальные изображения, иконки, стили и анимации находятся в `src`, `public`, `dist/client`. Подложка карты OpenStreetMap требует интернет; без него сама карта может быть пустой, но приложение и локальные данные остаются доступны.

## Доступ к внешним API

В ZIP **нет действующих ключей**. В корне создайте `.dev.vars` как копию `.dev.vars.example`, затем замените значения:

```powershell
Copy-Item .dev.vars.example .dev.vars
notepad .dev.vars
```

Обязательные для соответствующих функций переменные:

| Переменная | Для чего |
| --- | --- |
| `GEOAPIFY_API_KEY` | Геокодирование адреса новой заявки/стартовой точки и проверка точных дорожных маршрутов при изменении плана. |
| `YANDEX_AI_API_KEY` | Серверный API-ключ Yandex Cloud AI Studio для AI-помощника. |
| `YANDEX_AI_FOLDER_ID` | ID каталога Yandex Cloud, где разрешён доступ к модели; это **не** ID ключа. |
| `BEEGO_AI_MAX_PER_HOUR`, `BEEGO_AI_MONTHLY_TOKEN_BUDGET` | Локальные лимиты обращений к AI. |

После редактирования `.dev.vars` перезапустите оба процесса. AI вызывается только на сервере через `server/aiStudio.mjs` (`llm.api.cloud.yandex.net`), ключ не должен попадать в `src`, `public`, Git или ZIP. Отправляемый запрос содержит вопрос и ограниченный снимок показателей смены; перед использованием с реальными персональными данными проверьте требования организации к передаче данных в облако. Проверить конфигурацию AI можно в интерфейсе или запросом `GET /api/shifts/{shiftId}/ai/status`.

Если Geoapify не настроен, базовый просмотр и часть уже сохранённых планов доступны. **Геокодирование новых адресов и публикация пересчитанных маршрутов могут быть заблокированы**. Никаких выдуманных координат или дорог приложение для такой публикации не подставляет. Вместо Geoapify можно подключить совместимый локальный дорожный сервис через `VALHALLA_ROUTE_ENDPOINT`, но сам Valhalla и тайлы в архив не входят.

## Что сохранено, а что меняется

- `src/`, `public/`, `dist/client/` — все страницы и ресурсы интерфейса, включая «Ход смены», списки, карты, аналитику, модальные окна и стили.
- `worker/index.js` — адаптер запросов планирования и геокодирования; `server/operationsApi.mjs`, `server/shiftStore.mjs`, `server/roadRouting.mjs`, `server/aiStudio.mjs` — логика смены, версии планов, факты визитов, сотрудники, проверка дорог и AI.
- `.beego-data/shifts.sqlite3` — **согласованный снимок** действующей базы на момент упаковки. Он включает демонстрационные/пользовательские заявки, инженеров, версии планов, черновики, факты, отчёты и прочее локальное состояние. Не публикуйте ZIP в открытом доступе. Работа на другом ПК создаст **независимую копию** базы; синхронизации между ПК нет.
- `public/data/beego-exact-plans.json` — старый готовый результат для текущей демонстрационной выборки. Это переходный артефакт, не новый алгоритм. Его можно убрать **после** подключения нового алгоритма и проверки исходного планирования.
- `package.json`, `package-lock.json`, `vite.config.mjs`, `scripts/dev-api.mjs`, `server/main.mjs`, `.dev.vars.example` — воспроизводимый запуск.
- `tests/`, `docs/` — регрессионные проверки и описание текущих экранов/контрактов.

В архиве **нет** `.dev.vars`, `node_modules`, `.git`, старых `algorithm/`, `valhalla-data/`, `runtime/`, `data/`, `models/`, исходных выгрузок и временных логов. Некоторые команды в исходном `package.json` (`test:algorithm`, `build:planning-artifact`, `build:ml-forecast`) относятся к исключённому старому стеку и для этого комплекта не предназначены. Для сборки интерфейса используйте `npm run build`.

## Как подключить новый алгоритм

Не нужно переписывать экраны: сохраните HTTP-контракты.

1. Первичный расчёт: `POST /api/plan` с JSON `{ orders, engineers, regionId, options }`. Его сейчас обрабатывает `worker/index.js`. Ответ должен содержать `routes`, `unassigned`, `metrics`, статус `EXACT_VALID`/`HYBRID_VALID`/`HEURISTIC_VALID`, `publicationAllowed: true` и `validation.status: "VALID"` только после реальной проверки ограничений. Формы объектов смотрите в `public/test-data/`, `docs/algorithm-integration.md` и существующем обработчике. Недостоверный результат возвращайте как ошибку, а не как «валидный» план.
2. Изменение опубликованной смены: `POST /api/shifts/{id}/preview` с `expectedRevision` и `event` создаёт черновик; `GET /api/previews/{id}` сообщает результат; `POST /api/shifts/{id}/publish` публикует **проверенный** черновик. Оркестрация находится в `server/operationsApi.mjs`, модель события — `src/shiftDomain.js`, текущая вставка — `src/dynamicReplanner.js`, дорожная проверка — `server/roadRouting.mjs`. Новый алгоритм следует подключать на уровне расчёта кандидата (`routing`/`buildDynamicReplan`), не обходя версионирование и независимую проверку окна, навыка, зоны, смены и дороги.
3. `POST /api/geocode` оставьте для подтверждённого определения координат по адресу. `POST /api/reassign` сейчас лишь сообщает, что нужен проверяемый пересчёт; ручное назначение проходит через событие смены и публикацию. Сохраните возврат понятных ошибок для интерфейса.
4. Не меняйте без миграции таблицы `shifts`, `plan_versions`, `shift_events`, `visit_facts`, `replan_previews`, `staff_roster`: интерфейс читает историю, статусы и черновики из них. Для отдельного алгоритмического сервиса используйте серверный адаптер, а не вызовы из браузера. Секреты сервиса храните только на сервере.

В обоих вариантах запуска (`vite.config.mjs` и `scripts/dev-api.mjs`) импортируется один `worker/index.js` и один `server/operationsApi.mjs`; изменение этих модулей попадёт в оба API. Для развёртывания одним сервером можно выполнить `npm run build`, затем `npm run start:server`: он отдаёт `dist/client` и API на 8787. Так же не нужен отдельный Vite-процесс. В `server/main.mjs` файл `.dev.vars` читается сервером при старте.

## Краткая проверка после переноса

1. Откройте `http://127.0.0.1:5175/?date=2026-08-17`. Проверьте вкладки «Заявки», «Инженеры», «Ход смены», «Аналитика», «Данные», «Планирование», всплывающие карточки и карту.
2. Проверьте `http://127.0.0.1:5175/api/health` и `http://127.0.0.1:8787/api/health`: ожидается HTTP 200. Проверка API говорит только о доступности адаптера, **не** о том, что новый алгоритм уже подключён.
3. В «Ход смены» откройте сохранённую дату, просмотрите бригады, заявки, план, факты и журнал. Для нового события: создать черновик → дождаться дорожной проверки → публикация. При отсутствии настроенного дорожного сервиса остановитесь на просмотре: не считайте ошибку публикации потерей данных.
4. Для AI проверьте статус после настройки ключей. Для нового адреса проверьте геокодирование с Geoapify. На чужом ПК сначала используйте **копию** базы, а не производственные данные.

Состав ZIP и контрольные суммы каждого файла — `PACKAGE_MANIFEST_SHA256.tsv`. Рядом с ZIP лежит файл `.zip.sha256` для проверки целостности всей передачи.
