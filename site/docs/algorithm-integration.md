# Интеграция планировщика с сайтом

Актуальное описание конвейера, ограничений и барьера публикации — в [docs/planning.md](../../docs/planning.md). Источники маршрутов и пределы расписаний — в [docs/data.md](../../docs/data.md).

Сайт передаёт заявки и инженеров серверу. Для новых данных Node.js запускает Python-ядро с OR-Tools и локальным маршрутизатором, получает проверенный артефакт, показывает результат на карте и сохраняет опубликованную версию в SQLite. Исходный контрольный день 17.08.2026 содержит **205 заявок, 205 назначений и 32 активные бригады**. Это текущий комплект; цифры 200/205 и 204/205 относятся к прежним этапам проекта.

Публикация требует одновременно `status=EXACT_VALID`, `publicationAllowed=true`, `validation.status=VALID`, контрольную сумму и отсутствие приблизительных поездок. Поисковые матрицы не публикуются как итог. Непрошедший проверку или незавершённый расчёт оставляет прежнюю версию плана. Событийное изменение проходит через черновик и отдельное подтверждение.

На стенде API один, поэтому второй одновременный запуск получает `429 PLANNING_BUSY`. Недельные снимки МЦК/МЦД позволяют считать новые даты по эталону того же дня недели; это явное допущение, не точное историческое расписание.

Проверки из `site/`: `pnpm run test:algorithm`, `pnpm run test:sites`, `node --test tests/planning-slot.test.mjs tests/shift-operations.test.mjs`, `pnpm run build`.
