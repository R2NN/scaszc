# Визуальная иерархия карты BeeGo!

## Цель

Карта должна сначала отвечать на вопрос «что происходит в городе», затем — «где работает выбранная бригада», и только на рабочем масштабе показывать порядок остановок. Цвет не дублирует номер маршрута и не превращает обзор в мозаику.

## Режимы

- **Фокус** — режим по умолчанию. Все маршруты и назначенные точки нейтрально-серые. Выбранный маршрут — насыщенно-фиолетовый с тонкой жёлтой обводкой, белыми стрелками направления и пронумерованными остановками.
- **Цвета бригад** — дополнительный режим только при восьми или менее видимых маршрутах. Цвет маршрута детерминирован по `engineerId`. При большей выборке интерфейс автоматически возвращается в «Фокус».
- При выборе территории её полигон получает прозрачную жёлтую заливку, широкую фиолетовую внешнюю линию и тонкую жёлтую штриховую внутреннюю линию.

## Масштабы и точки

1. **Город** (`zoom < 10.45`, нет выбранного маршрута): близкие точки объединяются в компактные агрегаты. Число внутри — количество заявок, не номер остановки.
2. **Район**: показываются отдельные контурные точки. Назначенные — нейтральные, неназначенные — с оранжевой штриховой обводкой, аварии — красные ромбы.
3. **Маршрут**: выбранная бригада остаётся поверх контекста; номера появляются только у её остановок и только с `zoom >= 10.25`.

Точки с полностью одинаковыми координатами получают стабильное экранное смещение. Стартовые точки используют `public/depot-marker-purple.png` без подписи «СТАРТ».

## Взаимодействия

- Непрерывное наведение на дорогу в течение трёх секунд временно подсвечивает соответствующий маршрут и бригаду; быстрое пересечение линии ничего не меняет.
- Наведение на точку только визуально синхронизирует строку списка: оно не открывает карточку и никогда не включает маршрут.
- Клик по назначенной точке выбирает только заявку. В карточке есть отдельная кнопка «Показать маршрут бригады».
- Клик по дороге выбирает маршрут.
- Клик по свободному месту карты снимает выбор, закрывает карточки и возвращает дороги и точки к серому обзору.
- Повторный клик по выбранной точке закрывает её карточку.
- Первый выбор бригады вписывает в полезную область только её маршрут и старт, с ограничением максимального приближения. Последующие клики по остановкам и ручные изменения камеры не запускают повторное вписывание.
- При выборе маршрута нужная бригада раскрывается, прокручивается в видимую область списка и получает жёлтое выделение.

## Производительность

- GeoJSON-источник маршрутов обновляется через `setData`, слои не пересоздаются при каждом выборе.
- DOM-маркеры не пересоздаются при переключении активного маршрута; состояние обновляется классами и CSS-переменными.
- Точки агрегируются на городском масштабе, а номера не рендерятся без активного маршрута.
- Состав городских кластеров считается в мировых Web Mercator-пикселях, а не относительно окна карты: панорамирование не меняет группы. Пересчёт выполняется после завершения движения/масштабирования; CSS не анимирует служебный `transform` MapLibre.
- Невидимый слой попадания дороги отделён от визуального слоя, поэтому линия остаётся тонкой, а выбрать её удобно.
- Анимации камеры проходят через единый оптимизированный вызов и учитывают открытые боковые панели.

## Референсы реализации

Использованы официальные паттерны MapLibre:

- [Hover styles и feature state](https://maplibre.org/maplibre-gl-js/docs/examples/hover-styles/)
- [Кластеры с пользовательскими свойствами](https://maplibre.org/maplibre-gl-js/docs/examples/cluster-html/)
- [Рекомендации для больших наборов GeoJSON](https://maplibre.org/maplibre-gl-js/docs/guides/large-data/)
- [GeoJSONSource: expansion zoom и leaves](https://maplibre.org/maplibre-gl-js/docs/API/classes/GeoJSONSource/)

В текущем прототипе кластеризация выполняется детерминированной экранной сеткой, потому что точки уже являются интерактивными DOM-маркерами с карточками. Это сохраняет существующий контракт кликов, но следует той же иерархии масштабов.

## Проверки

- unit-тесты токенов, стабильной палитры, границ режимов и группировки: `npm run test:map`;
- контракт импорта и Sites-сборки: `npm run test:sites`;
- точный планировщик на исходном и событийном сценарии: `npm run test:algorithm`;
- production-сборка: `npm run build`;
- визуальная проверка: 1366×768, 1440×900, 1920×1080, 3440×1440, светлая и тёмная темы.
