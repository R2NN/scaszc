# Ход смены: запуск и сохранность данных

## Один сервер

Для операционных сценариев запускайте Node-сервер, а не только статическую
сборку Sites: `npm ci`, `npm run build`, `npm run start:server`. По умолчанию
сервер слушает `127.0.0.1:8787`; при публикации наружу используйте HTTPS и
обратный прокси с аутентификацией. Операционный API пока не содержит
пользовательских учётных записей и не должен быть открыт в Интернет напрямую.

Хранилище SQLite по умолчанию — `.beego-data/shifts.sqlite3`. Для постоянного
тома задайте `BEEGO_DB_PATH` абсолютным путём; не размещайте базу внутри
пересоздаваемого каталога сборки. Сервер записывает версии плана, события и
фактические отметки транзакционно. После перезапуска интерфейс загружает смену
по паре «регион + дата». Незавершённый на момент перезапуска расчёт помечается
ошибкой, его можно создать повторно; опубликованный план не меняется.

## Дорожная проверка и AI

Для точной проверки изменённых маршрутов настройте серверный
`GEOAPIFY_API_KEY` либо локальный `VALHALLA_ROUTE_ENDPOINT`. Если точный
дорожный ответ недоступен или визит не помещается в окно/смену, черновик не
публикуется. Исходный `/api/plan` сохраняет собственные обозначения
`EXACT_VALID` и `HYBRID_VALID`; оценочные участки не выдаются за точные.
Публикация операционного события проверяет реальные дороги на всех изменённых
будущих участках. Неизменённые участки расширенного исходного плана могут
оставаться оценочными: их число явно показывается в черновике и хранится в
версии плана. При недоступности дорожного сервиса новые участки не публикуются.
Черновик хранится как фоновая задача: интерфейс показывает этап и число реально
проверенных дорожных участков. После ухода со вкладки состояние расчёта можно
восстановить, но публикация остаётся отдельным действием диспетчера.

AI необязателен. Для него нужны **оба** серверных параметра:
`YANDEX_AI_API_KEY` и `YANDEX_AI_FOLDER_ID`. Идентификатор API-ключа не
заменяет ID каталога. Ключ не записывайте в исходники, `.dev.vars.example` и
клиентскую сборку. Перед общедоступным развёртыванием перевыпустите ключ,
который уже был опубликован в переписке. Без AI отчёт и пересчёт работают.
Число обращений ограничено `BEEGO_AI_MAX_PER_HOUR` (по умолчанию 10 на смену).
Сервер также учитывает токены в SQLite и резервирует бюджет перед запросом:
`BEEGO_AI_MONTHLY_TOKEN_BUDGET` (по умолчанию 240000 токенов в месяц). Это
технический лимит потребления, не гарантия фиксированной цены в рублях.

В левом меню «Ход смены» отвечает за карту, события, факты и откат. В отдельном
разделе «Отчёт и AI» есть две вкладки: «Чат с AI» с историей вопросов и быстрыми
подсказками и «Отчёт PDF» с проверяемыми показателями, генерацией и скачиванием.
PDF включает рабочие часы и нагрузку всех бригад, структуру заявок по зонам и
работам, реестр назначенных визитов, очередь с причинами, отмены, неуспешные
визиты и журнал изменений. Встроенный предпросмотр показывает страницы порциями,
чтобы документ на 200+ заявок не тормозил страницу; скачать можно весь файл.
При изменении версии плана или фактов старый PDF и AI-диалог сбрасываются,
чтобы не показывать ответ по устаревшему снимку. AI не публикует изменения.

## Резервная копия и восстановление

`npm run backup:shifts` создаёт согласованную SQLite-копию в
`.beego-backups/`; можно передать явный путь после `--`. Проверяйте наличие
копии и храните её отдельно от сервера. Для восстановления:

1. Остановите Node-сервер, чтобы не перезаписать активные данные.
2. Сохраните текущий файл базы отдельно, не удаляя его.
3. Скопируйте проверенный файл резервной копии на путь `BEEGO_DB_PATH`.
4. Запустите сервер и проверьте смену по дате и региону, журнал событий,
   версии плана и фактические отметки.

Автотест `tests/shift-operations.test.mjs` проверяет именно такой цикл:
публикация, факт, SQLite backup, копирование и чтение после нового запуска.

## Границы первой версии

Факт вводит диспетчер; проигрывание по плану не создаёт фактических статусов.
Импорта факта и личного кабинета инженера здесь нет. На публичном сервере
нужны HTTPS, аутентификация перед приложением, регулярные копии и мониторинг
диска/ошибок. Для демонстрации локально эти внешние службы не требуются.
