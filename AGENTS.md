# Работа с BeeGo!

## Навигация

- `README.md` — продукт, сценарии и актуальные экраны.
- `docs/README.md` — единый указатель документации.
- `site/` — React/MapLibre, Node API и JS-тесты; дополнительные правила в `site/AGENTS.md`.
- `algorithm/` — Python-планировщик, маршрутизация, инструменты и тесты.
- `data/` — входы, модели транспортных данных и проверяемый runtime-комплект.
- `runtime/`, `tools/`, `deploy/` — запуск маршрутизатора, установка ресурсов и серверное развёртывание.

## Разработка

- Использовать pnpm и зафиксированный `site/pnpm-lock.yaml`; не добавлять production-зависимости без согласования.
- После изменения исходников запускать относящиеся к ним тесты. При изменении поставки проверять сборку и комплектность ресурсов.
- В JavaScript/TypeScript использовать одинарные кавычки и async/await. Новые TypeScript-файлы писать в строгом режиме.
- Для экспортируемых функций добавлять JSDoc, когда он объясняет контракт. Не оставлять закомментированный код и отладочные сообщения.
- Каждую задачу выполнять в отдельной ветке `codex/…`; коммиты — conventional commits. Не делать force-push в `main`/`master`.
- Отвечать и писать интерфейс на русском языке.

## Сохранность и воспроизводимость

- Публиковать только независимо проверенные планы. Сохранять навыки, транспорт, окна клиентов, факты выполнения и историю версий.
- Не подменять расчёт примером с другими данными. Сохранённые планы связаны с SHA-256 входов и транспортных данных.
- Не менять байты наборов с `CHECKSUMS.sha256` ради форматирования. Сохранять правила `.gitattributes`.
- Рабочие SQLite, ключи, пользовательские резервные копии, кэши, логи и локальные прогоны не добавлять в Git.
- Генерируемые материалы проверок складывать в `output/`, а не в исходники и документацию. Полезный итог переносить в техническую справку.
- При обновлении README сохранять его структуру и логику рассказа. Изменившиеся экраны переснимать из текущего приложения в 1920×1080 или выше; не подставлять вымышленные результаты.

Команды разработки и проверки: [docs/development/contributing.md](docs/development/contributing.md).
